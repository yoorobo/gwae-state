## 1. 클로 세션 진입 (3종)

에이전트별 진입 방식이 다르다. 레오(CLAUDE.md)·도우(AGENTS.md)·차이(프로젝트 소스+지침)는
도구가 세션 시작 시 자동 로드한다. 클로는 프로젝트 커스텀 지침이 자동 주입되나, 진실원
fetch는 클로가 능동 실행해야 한다. 이를 3종으로 규정한다.

### A. 자동 진입 (신규 창)
- 프로젝트 커스텀 지침이 자동 주입됨.
- 클로는 첫 응답 전 `_INDEX` · `STATE` · `HANDOFF`를 web_fetch로 읽고 시작. 설명 0회.
- 진실원을 읽기 전에는 하네스·상태에 관한 판단을 하지 않는다(추측 금지).
- web_fetch가 raw URL 직접 접근에 실패하면: 검색 경유 시도 → 그래도 실패 시 정학에게
  붙여넣기 요청. 읽지 못한 채 추측하지 않는다.

### B. '이어가기' (명시적 인수인계)
- A와 동일 동작. 정학이 명시적으로 트리거하는 프로젝트 컨텍스트 복귀 명령.

### C. '하네스' (거버넌스만 재로드)
- `_INDEX` + `_operations/` 전체만 다시 읽는다. 프로젝트 상태(STATE)는 읽지 않는다.
- 용도: 헌법이 방금 바뀐 직후 클로를 최신 거버넌스로 동기화.
- 재로드 후 "v1.x → v1.y, 무엇이 변경" 한 줄 보고.

### 진입 명령 계층
- '하네스' = 전역 거버넌스 로드 (프로젝트 무관, 단독 실행 가능)
- '○○ 이어가기' = _INDEX(헌법) 확인 후 → 프로젝트 STATE/HANDOFF 로드 (헌법 전제로 깔림)

## 2. G3(Build) 내 레오 플랜 게이트

### 라우팅 기준 (기존 라우팅 재사용)
- 버그픽스 · 위치명확 · 기술수정 → 플랜 게이트 **생략** (Codex 직접)
- 신규기능 · 다중파일(3+) · 맥락판단 → 플랜 게이트 **필수**

### 플랜 게이트 흐름 (필수 대상일 때)
```
정학 승인 (G2 통과)
  → 레오 [플랜 모드] 구현계획 제출 (뮤테이션 금지, ~/.claude/plans/ 저장)
  → 도우 플랜 검증
  → 클로 + 정학 최종 승인        (교차검증: reasoning 측 클로 + 결정권 정학)
  → 레오 구현 (뮤테이션 시작)
  → verify-task.sh 통과 후 머지
```

### 원리
- 레오의 첫 출력은 코드가 아니라 계획. 레오 내부에서도 reasoning(계획) ↔ mutation(구현) 분리.
- 빅테크 검증: 가이드 없는 시도는 약 33%만 성공. 3+ 파일이면 플랜 먼저가 표준.
- 플랜은 ~/.claude/plans/에 저장되어 컨텍스트 압축·세션 재시작에도 생존.

## 3. 하네스 자가수정 루프 (헌법/운영규칙 변경 시)

```
① 변경 발생 (클로 채팅 중)
② 클로 "하네스 적용?" 질문 → 정학 OK
③ 차이 1/0/2 (헌법 변경 검증 — 최상위 변경이므로 교차검증 필수)
④ 클로 → 도우 WO:
   - _operations 파일 수정/신규 + _INDEX 갱신 + 버전 올림
   - mirror sync.sh에 _operations 포함되도록 확장 (아래 4항)
⑤ 도우 완료 (Private gwae 수정 → Public gwae-state 미러 push)
⑥ 클로 확인
⑦ 정학 '하네스' 명령 → 클로 재로드 + "v1.x→v1.y, 변경점" 보고
```

### 원칙
- 헌법 변경은 모든 미래 세션에 영향을 주는 최상위 변경이므로 ③ 차이 교차검증 필수.
- 클로는 _operations 파일을 직접 수정하지 않는다(reasoning↔mutation 분리). 도우가 기록.
- 헌법에 버전 번호 부여. source(재로드) 성공 여부를 버전으로 확인.

## 4. mirror 파이프라인 확장 (현재 빠진 고리)

### 현황 (도우 조사 2026-06-14)
- `gwae/.git/hooks/post-commit`: STATE/PROJECT/DECISIONS/HANDOFF.md 커밋 시에만
  vault 복사 + public mirror(sync.sh) 자동 호출.
- `_state-mirror/sync.sh`: STATE.md, HANDOFF.md만 Public으로 복사·push.
- **문제: `_operations/`(운영규칙·헌법)는 자동 미러에 묶여 있지 않다.**
  → 헌법을 바꿔도 Public gwae-state로 자동 반영되지 않아, 클로가 web_fetch로
    최신 헌법을 못 읽는다.

### 확장 (도우 작업 대상)
- post-commit hook 트리거 조건에 `_operations/` 하위 변경 포함.
- sync.sh가 `_operations/` 디렉토리도 Public으로 복사·push하도록 확장.
- secret-guard.sh를 _operations 파일에도 적용 (비밀 유출 방어 유지).

## 5. WO 마무리 표준 (작업완료 → 클로 팔로업 연결)

### 문제
'작업완료'(정학) → 클로가 result.md 읽기 워크플로우가 작동하려면, 도우/레오가
작업 후 result.md를 Public(gwae-state)에 push해야 한다. 그런데 result.md 동기화는
post-commit 자동 hook에 안 묶여 있고(별도 sync-result.sh), WO에 명시 안 하면
도우가 result.md를 갱신하지 않는다. (2026-06-14 실측: _operations는 동기화됐으나
result.md는 last week 그대로 — WO에 result.md 지시가 없었기 때문.)

### 규칙 (모든 도우/레오 WO 끝에 표준 삽입)
1. 검증 결과를 `handoff/result.md`에 좌표 형식으로 기록(덮어쓰기, 이전 건 날짜 백업).
2. `sync-result.sh` 실행하여 result.md를 gwae-state Public에 push.
3. 검증 결과 피드 Notion(`372f9b98-01ac-8198-98d9-df00187d5479`)에도 기록.
- 위 3단계가 없으면 '작업완료' 시 클로가 읽을 result.md가 갱신되지 않는다.
- 클로는 WO 작성 시 이 마무리 표준을 항상 포함한다.

## 6. WO 전달 경로 규칙 (이중 탐색 방지)

### 문제
클로 다운로드는 항상 `~/다운로드/` 평면에 떨어지는데, WO 전달 명령어에
`~/다운로드/프로젝트/category/` 하위구조를 적으면 도우·레오가 하위폴더에서
먼저 찾고 없으면 다시 평면에서 찾는 이중 탐색이 발생한다.

### 규칙 (전달 경로 = 평면 / 정리 경로 = NAMECARD dest)
- 클로 다운로드는 항상 `~/다운로드/` 평면에 떨어진다.
- WO 전달 복붙 명령어의 파일 경로 = 항상 `~/다운로드/파일명.md` (하위구조 금지).
- 폴더 분류(dest)는 NAMECARD 헤더에만 적는다.
- 실제 폴더 이동은 도우/레오가 파일을 연 뒤 NAMECARD의 dest를 확인 →
  폴더 없으면 생성 → 이동 후 작업.

## 7. 산출물 버전 규칙 (옛 파일 오용 방지)

### 문제
같은 이름 파일을 재다운로드하면 브라우저가 `파일명 (1).md`를 만들어,
도우·레오가 옛 파일을 집는 오류가 발생한다.

### 규칙 (버전 접미사로 최신본 식별)
- 같은 산출물을 수정 재생성 시 파일명 끝에 `_v2`, `_v3`... 접미사를 붙인다.
  (브라우저 자동 `(1)` 방지 + 최신본 식별)
- `MMDD_NN_category_제목`의 NN(번호)은 안 변함. 버전만 올린다.
- 초안은 접미사 없음(= v1 취급), 첫 수정부터 `_v2`.
  예: `0614_01_WO_제목.md` → 수정 → `0614_01_WO_제목_v2.md`
- 도우/레오는 항상 가장 높은 `_vN`을 최신으로 사용. 낮은 버전·`(1)` 파일은 무시.
- NAMECARD 헤더에 `version` 필드 추가 (예: `version: v2`).

## 8. 진실원 경로 (확정)

- 운영규칙 인덱스: `raw.githubusercontent.com/yoorobo/gwae-state/main/_operations/_INDEX.md`
- 상태: `.../STATE.md` (현재 사실) / `.../HANDOFF.md` (흐름·맥락)
- 검증 결과 피드: Notion `372f9b98-01ac-8198-98d9-df00187d5479` (도우 쓰기 허용 유일)
- 운영 헌법: Notion `372f9b98-01ac-81ad-bb75-c29b00c17c49` (클로 읽기 한계, 정학 요약 붙여넣기)

### 클로 fetch 연쇄 접근 메커니즘 (_INDEX 링크 허브)
- 클로 web_fetch는 "이전 검색/fetch 결과에 등장한 URL"만 호출 가능(도구 제약, public 무관).
- 따라서 `_INDEX.md` 최상단에 STATE/HANDOFF/result의 full raw URL을 명시(링크 허브化).
- 클로 '이어가기' 시: ① _INDEX fetch → ② 결과에 등장한 STATE/HANDOFF/result URL을
  연쇄 fetch. 이로써 정학 수동 붙여넣기 없이 진실원 직접 접근.
- 폴백: 연쇄 fetch 실패 시 정학이 해당 파일 내용 붙여넣기.
