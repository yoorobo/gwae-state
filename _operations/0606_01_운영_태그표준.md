# 운영체계 #01 — 태그 표준 (NAMECARD v3)

> **목적**: CASHMONTH의 모든 산출물을 "생성 시점에" 분류·번호·상태로 박제한다.
> 나중에 몰아서 정리하지 않는다(born-organized). 결국 에이전트(도우 등)가 이 규칙으로 자동 분류·정렬한다.
> **적용 범위**: GWAE를 포함한 모든 CASHMONTH 실험체. 제품이 바뀌어도 이 규칙은 유지.

---

## 핵심 원리 — 두 가지를 분리한다

| 구분 | 무엇 | 어디에 | 변하는가 |
|---|---|---|---|
| **분류 태그** | 종류 + 번호 | **파일명** | ❌ 안 변함 (ADR-014는 영원히 ADR-014) |
| **상태 태그** | todo/doing/done/parked/archived | **파일 안 헤더** | ✅ 변함 (시간 따라 이동) |

**왜 분리하나**: 상태를 파일명에 박으면 상태 바뀔 때마다 파일명을 바꿔야 함(지옥). 분류는 파일명에 고정, 상태는 헤더에서만 움직인다.

---

## 1. 파일명 규칙 (안 변하는 분류)

```
MMDD_NN_category_제목.md

예: 0606_05_운영_독해지도.md
    └날짜 └번호 └종류  └제목
```
- **MMDD**: 생성 날짜 (폴더 자동 정렬용)
- **NN**: 2자리 일련번호, 01부터 (생성 순서)
- **category**: 아래 9종 중 하나
- **제목**: 짧게, 공백 대신 없음/언더바

## 1-1. 버전 접미사 규칙 (_vN) — 신규

파일명 끝에 버전 접미사를 붙인다. 내용이 바뀔 때마다 v만 올린다.

    MMDD_NN_category_제목_vN.md
    예: 0607_18_기획_SR1무료코어_v2.md

- **NN(번호)·category는 불변** (산출물 정체성). 버전이 올라가도 번호는 그대로.
- **_vN(버전)은 내용이 바뀔 때만 올림** (v1→v2→v3). 변경 이력 담당.
- 최초 생성 = `_v1`. (혹은 v 생략 = v1 간주. 단 재배포 가능성 있는 산출물은 처음부터 _v1 권장.)
- **같은 내용 재다운로드 금지**: 이미 받은 버전을 또 받지 않는다. 내용이 그대로면 새 v를 만들지 않는다 → 브라우저 (1)(2) 누적 원천 차단.
- 최신본 = 가장 높은 _vN. 정학·에이전트 모두 이 기준으로 최신 식별.
- 같은 산출물 수정 재생성 시 파일명 끝에 _v2, _v3 접미사. NN(번호)은 불변, 버전만 상승.
  초안=접미사 없음(v1), 첫 수정부터 _v2. 도우/레오는 항상 가장 높은 _vN 사용,
  낮은 버전·"(1)" 파일 무시. NAMECARD에 version 필드 추가.

역할 분담(충돌 방지):
- NN = 산출물이 무엇인가 (불변)
- _vN = 그 산출물이 몇 번째 개정인가 (가변)
- status 헤더 = 그 산출물이 지금 어느 단계인가 (가변)
세 축이 각각 정체성/이력/상태를 담당해 서로 부딪히지 않는다.

에이전트 적용:
- 레오·도우·클로 전원, 산출물 생성·수정 시 _vN 부여.
- 파일 옮길 때(dest) 동일 NN의 더 낮은 v는 _archive로 이동 또는 보관, 최신 v만 작업대에 노출(선택).

## 4. 상태 5값 (확정)

| status | 뜻 |
|---|---|
| `todo` | 만들기로 했으나 아직 시작 안 함 |
| `doing` | 지금 작업 중 |
| `done` | 완료, 현역으로 쓰임 |
| `parked` | 갈래로 보류 (신호어 "파킹"과 연결). 나중에 다시 꺼냄 |
| `archived` | 끝났고 더 안 씀. 근거 보관만 |

## 5. 에이전트 처리 (나중에 도우가 함)
- 파일명 `NN` → 순서·종류 자동 정렬
- 헤더 `status` → todo/doing/done/parked/archived 자동 분류 (칸반)
- 헤더 `source` → 원본 역추적
- WO 전달 복붙 명령어의 경로는 항상 ~/다운로드/파일명.md (평면). 하위구조 금지.
  폴더 분류는 NAMECARD dest에만 적고, 실제 이동은 도우/레오가 파일 열어 dest 확인 후 수행.
