# 운영체계 #01 — 태그 표준 (NAMECARD v2)

> **목적**: CASHMONTH의 모든 산출물을 "생성 시점에" 분류·번호·상태로 박제한다.
> 나중에 몰아서 정리하지 않는다(born-organized). 결국 에이전트(도우 등)가 이 규칙으로 자동 분류·정렬한다.
> **적용 범위**: GWAE를 포함한 모든 CASHMONTH 실험체. 제품이 바뀌어도 이 규칙은 유지.

---

## 핵심 원리 — 두 가지를 분리한다

| 구분 | 무엇 | 어디에 | 변하는가 |
|---|---|---|---|
| **분류 태그** | 종류 + 번호 | **파일명** | ❌ 안 변함 (ADR-014는 영원히 ADR-014) |
| **상태 태그** | todo/doing/done/parked/archived | **파일 안 헤더** | ✅ 변함 (시간 따라 이동) |

**왜 분리하나**: 상태를 파일명에 박으면 상태 바뀔 때마다 파일명을 바꿔야 함(지옥). 분류는 파일명에 고정, 상태는 헤더에서만 움직인다.

---

## 1. 파일명 규칙 (안 변하는 분류)

```
MMDD_NN_category_제목.md

예: 0606_05_운영_독해지도.md
    └날짜 └번호 └종류  └제목
```
- **MMDD**: 생성 날짜 (폴더 자동 정렬용)
- **NN**: 2자리 일련번호, 01부터 (생성 순서)
- **category**: 아래 9종 중 하나
- **제목**: 짧게, 공백 대신 없음/언더바

## 2. 헤더 규칙 (변하는 상태 + 출처 추적)

모든 .md 파일 맨 위:
```
---NAMECARD
status: doing
category: 운영
number: 05
date: 0606
agent: 클로
source: GWAE합본 L12696 또는 신규
---
```
- **source 필드가 핵심** → 이 자료가 어디서 나왔는지 역추적(provenance). 합본 줄번호 또는 "신규".

## 3. category 9종 (확정)

| category | 들어가는 것 |
|---|---|
| 기획 | 사업기획서, 리서치, 연구의뢰서, 결정서 |
| ADR | 아키텍처 결정기록 (ADR-NNN) |
| 작괘 | 작괘엔진 코어·코드 자산 |
| 운영 | 운영체계·규칙·헌법·태그표준 (이 문서) |
| 마케팅 | 타겟·채널·컨셉·레딧/광고 전략 |
| 랜딩 | 랜딩 index.html·GA4·Formspree·UTM·배포 |
| 광고 | 광고 소재(reel)·캠페인 설정·판정기준 |
| WO | 도우·레오에게 보낸 작업지시서 |
| 보고서 | 종합 서사·PM 보고서 |

## 4. 상태 5값 (확정)

| status | 뜻 |
|---|---|
| `todo` | 만들기로 했으나 아직 시작 안 함 |
| `doing` | 지금 작업 중 |
| `done` | 완료, 현역으로 쓰임 |
| `parked` | 갈래로 보류 (신호어 "파킹"과 연결). 나중에 다시 꺼냄 |
| `archived` | 끝났고 더 안 씀. 근거 보관만 |

## 5. 에이전트 처리 (나중에 도우가 함)
- 파일명 `NN` → 순서·종류 자동 정렬
- 헤더 `status` → todo/doing/done/parked/archived 자동 분류 (칸반)
- 헤더 `source` → 원본 역추적
